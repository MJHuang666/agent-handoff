# Knowledge Index

This file is the index of durable project knowledge, not a second architecture document or a chat transcript. Every entry must link to its still-authoritative source and reviewable evidence; do not duplicate full prose here.

## Rules

1. Start every task by reading `PROJECT_STATUS.md`, then skim this index; open only sources relevant to the current task afterward.
2. The Planner proposes durable architecture, constraint, or decision candidates in `tasks/<TASK-ID>/decisions.md`. Unverified ideas must not be marked `ACTIVE`.
3. During `VERIFYING`, the Reviewer promotes an entry here only when both delivery and evidence are verified and the conclusion will be reusable across tasks.
4. When a new conclusion replaces an old one, mark the old entry `SUPERSEDED` and link its replacement. Mark an inapplicable entry `RETIRED` when it has no replacement. Keep IDs; never silently delete history.

## Statuses

- `ACTIVE`: current and safe to rely on.
- `SUPERSEDED`: explicitly replaced by a newer entry; retained for auditability.
- `RETIRED`: no longer applicable; do not use for new work.
